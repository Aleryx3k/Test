# Отчёт о функциональном тестировании «Учёт оборудования»

## Что сделано

| Часть | Что это | Где лежит | Статус |
|---|---|---|---|
| **A** | 122 теста «нажатий»: вызываются настоящие команды окон (кнопки), результат проверяется по базе SQLite | `tests-to-copy/EquipmentAccounting.FunctionalTests` | Запущено на Linux: **117 прошли, 2 нашли проблемы, 3 пропущены (нужна Windows)** |
| **B** | 6 тестов настоящего окна: запускают `EquipmentAccounting.exe` и кликают через UI Automation (FlaUI) | `tests-to-copy/EquipmentAccounting.UiTests` | **Только собран. Не запускался** (нужна Windows). Может потребовать правок |

Обычные тесты проекта (`tests/EquipmentAccounting.Tests`, 5 штук) тоже прошли.

## Что именно проверяет часть A

- **Вход и регистрация**: неверный пароль, пустые поля, занятый логин, слабый пароль, заблокированный пользователь.
- **Администрирование**: добавление, правка, блокировка, удаление аудиторий, пользователей, категорий, типов, состояний, рабочих мест; отмена правок; поиск; настройки почты; Excel; защита администратора от самоблокировки.
- **Оборудование**: добавить, изменить, копировать, удалить; проверка полей; фильтры и поиск; фото (не больше 3); характеристики; блокировка; выгрузка карточки и списка в Excel/PDF/HTML; заявки из карточки.
- **Права доступа**: преподаватель не видит и не может менять чужие аудитории, оборудование, заявки.
- **Рабочие места, Заявки, Профиль, Главная, Меню, Отчёты (все виды × 3 формата), Диаграммы**.

После каждого действия проверяется, что данные реально сохранились в базе, а не только показаны на экране.

## Найденные проблемы

### 1. Серьёзно: администратор с известным паролем создаётся заново при каждом запуске
`DbInitializer.cs`: если в базе нет пользователя с логином по умолчанию, при запуске программа создаёт его с паролем по умолчанию, который записан в исходном коде и в README.

Что это значит: если владелец сменит логин администратора (или удалит запись), при следующем запуске появится новый администратор с паролем, известным каждому, кто видел код или README. Тест `Если_переименовать_администратора_после_перезапуска_...` это воспроизводит.
Смена **пароля** без смены логина безопасна (тест проходит).

Что сделать: создавать администратора только при совсем пустой базе (нет ни одного пользователя) и требовать смену пароля при первом входе; пароль по умолчанию не хранить в коде и README.

### 2. Серьёзно: пароли и данные лежат в репозитории
- В `README.md` внутри архива указан логин и пароль администратора.
- В архиве есть файл `доступ.txt`, похожий на список паролей (содержимое я не читал: доступ к нему заблокировала защита).
- В архив попала папка `publish/` с рабочей базой `equipment.db` (2 пользователя, 16 аудиторий, 207 позиций оборудования) и папки `bin/obj`.
- Всё это уже в истории git. Удаление файла историю не очищает.

Что сделать: считать эти пароли скомпрометированными и сменить; сделать репозиторий закрытым (если он публичный); не коммитить `publish/` и базу.

### 3. Мелкое: номера рабочих мест различаются по регистру
Места «A1» и «a1» в одной аудитории сохраняются как два разных (логины и номера аудиторий сравниваются без учёта регистра). Заодно латинская «A» и кириллическая «А» выглядят одинаково, но считаются разными. Тест `Номер_рабочего_места_в_другом_регистре_считается_дублем`.

## Замечания (не ошибки)
- При добавлении оборудования тип не выбран по умолчанию: надо выбрать вручную (иначе «Выберите тип оборудования»).
- ПИН-код хранится через защиту данных Windows (DPAPI): на другой системе не работает. Это нормально для программы только под Windows.

## Что НЕ проверено
- **Внешний вид и окна**: расположение кнопок, привязки в XAML, фото на экране, диаграммы, диалоги выбора файла. Это покрывает только часть B, и её нужно запускать вам.
- **Уменьшение фото** до 1600 px (в тестах заменено копированием файла).
- **Восстановление пароля по почте** (нужен настоящий SMTP-сервер).
- **Импорт из Access** (нужен Windows и файл базы Access).
- **ПИН-код** (3 теста; пропускаются на Linux и выполнятся на Windows).

## Как запустить

### Часть A (любая система, нужен .NET 8 SDK)
1. Скопируйте папку `tests-to-copy/EquipmentAccounting.FunctionalTests` в `EquipmentAccounting/tests/`.
2. В папке `EquipmentAccounting` выполните:
   ```
   dotnet test tests/EquipmentAccounting.FunctionalTests
   ```
Проект подключает исходники моделей окон из `src/EquipmentAccounting.Wpf` как есть. Ваши файлы не меняются.

### Часть B (только Windows)
1. Скопируйте `tests-to-copy/EquipmentAccounting.UiTests` в `EquipmentAccounting/tests/`.
2. Задайте переменные окружения (пароль в код не записан):
   ```
   set EA_LOGIN=ваш_логин
   set EA_PASSWORD=ваш_пароль
   set EA_EXE=C:\путь\к\publish\EquipmentAccounting.exe
   ```
   `EA_EXE` можно не задавать, если рядом есть папка `publish`.
3. Запустите: `dotnet test tests/EquipmentAccounting.UiTests`

Тесты копируют программу во временную папку, поэтому рабочая база не затрагивается. Не запускайте их с чужой боевой учётной записью.

Поля ввода находятся по порядку, а кнопки по подписи: в XAML нет `AutomationId`. Если тесты не находят элемент, надёжнее всего добавить `AutomationProperties.AutomationId` в окна. Могу сделать это отдельно.
